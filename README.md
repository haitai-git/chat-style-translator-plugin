# 聊天风格转译插件（Chat Style Translator）

绑定 QQ 群后自动收集群友对话，在后台用 LLM 分析「群友们在聊什么场景、每句话在跟谁说、每个群友的聊天风格」，生成可审核、可编辑、可融合的**风格模型**；通过**黑名单语义过滤**剔除含义不合的语句；审核通过并挂载后，**AI 的自身行为风格保持不变**，每次生成回复草稿后会检索该群风格，让 LLM 按可调强度做微调——原意严格不变。另有**微调前黑名单**：回复草稿中出现黑名单词时先在微调前删除（仅支持中文词条，可开启语义换词匹配保持原意），以及**回复乱码拦截**：防止乱码/指令残片被发到群里。

## 功能一览

- **对话收集**：绑定群后自动存储每位群友的消息（含 @ 对象、回复对象、上下文）。
- **历史消息回填（不用等实时收集）**：`/风格拉取历史 [群号] [条数]` 直接从 NapCat 拉取该群最近 N 条历史消息补进收集池；也可以在 WebUI 插件配置 → 收集与自动分析 →「立即执行历史回填」开关（打开并保存配置后自动对全部绑定群回填，完成后请关回开关）。回填执行与实时收集相同的屏蔽与字句黑名单过滤，并按消息 ID 去重；回填后达到自动分析条数会自动触发分析。需机器人在群里、NapCat 在线且该群允许获取历史记录。
- **后台转译分析**：三种触发方式——收集满 N 条消息自动分析、每天固定时间点自动分析、手动 `/风格生成`，以及 **WebUI 插件配置 → 收集与自动分析 →「立即执行分析」按钮**（开关打开并保存配置后，立即对全部绑定群执行一次后台分析；分析完成后请将开关关回）。 自动分析失败后，该群冷却五分钟，之后仍可触发每日任务。管理员可以在冷却期间手动执行。
- **存储上限自动清理**（WebUI 插件配置 → 收集与自动分析 →「每群存储上限」，默认 500）：每个群收集的消息超过上限后自动删除最旧消息，只保留最近 N 条，防止消息文件无限增长占用硬盘（后台每分钟兜底清理一次）——自动分析关闭、群又一直发言时也永远不会无限堆积。
- **分析提速（不改变内容）**：分批分析默认**并发 2 批**同时进行（WebUI 配置 → 分析参数 →「并发分析批数」，1~4），大幅缩短总耗时；也可调大「分析窗口条数」减少批次数。并发只加速、不改变分析内容。
- **分析总进度私聊通知**：所有触发方式（自动、WebUI 按钮、`/风格生成` 命令）的分析都按**总进度**私聊发送——「分析进度：已处理 X/总 Y 条（Z%）」，发送间隔可在 WebUI 配置 → 分析参数 →「进度通知间隔（秒）」调整（默认 120 秒 ≈ 每 2 分钟一次；填 0 = 每批完成都发送；首批完成后必发一次）。进度与最终结果**私聊发送**给「进度私聊 QQ 号」填写的 QQ；该 QQ 与 bot 不是好友时**静默不发送**；留空则完全不发送进度（也不会发到群里）。`/风格生成` 与 `/风格拉取历史` 命令改为**后台执行并立即回复**（避免命令超时），进度与结果全部走私聊推送。
- **场景化风格模型**：一个模型包含多个场景，每个场景有风格描述、场景备注、代表性语句（注明说话人、说话对象、语句意思与 AI 理解备注）与群友个人风格档案。
- **多模型融合**：`/风格合并` 把多份模型融合成一份，相似场景与相似含义的语句自动合并去重；也可以在 WebUI 插件配置 → 模型融合 中填写模型 A/B 并打开「执行融合」，保存配置后自动后台融合。融合时可配置**融合比例滑块（A:B）**：两模型含义相同的重复语句只保留一条并按比例优先保留某一方的表述；**去重强度**：标准 / 激进精简（相近含义也合并，体积更小）/ 不去重。程序会从输入补回遗漏的独立范例及其前文。融合请求会跳过同一场景下跨模型的完全重复范例，保留不同前文。融合后的风格摘要和来源快照可一起保存。
- **单模型精简（模型太大时压缩体积）**：WebUI 插件配置 → 模型精简，填写「要精简的模型」并打开「执行精简」开关，保存配置后自动后台把该模型内**相似场景、近似语句、相似风格快照**合并去重——相似或重复的场景必定合并，与其原来源/时段无关（纯本地处理、不调用 LLM、不改变语句内容，秒出结果），并执行字句与语义黑名单过滤。语义过滤可能调用模型。可调去重强度（标准 / 激进精简 / 不去重）、场景合并阈值与风格快照合并阈值。精简结果生成全新的模型文件（原模型不动，状态 pending），审核后 `/风格启用` 挂载即可。
- **模型文件可编辑**：模型以 JSON 文件保存在模型目录（可配置），你可以直接打开编辑、重命名或增删模型文件，改动立即生效。
- **生效模型顺序**：开启「模型目录自动生效」时，所有群使用目录内全部可读的风格模型。群聊通用与群挂载设置会暂时停用，关闭目录模式后恢复。新安装默认关闭目录模式。
- **模型按文件名引用**：模型可用文件名、模型名（支持前缀）或模型 ID 引用，例如 `/风格启用 1`、`/风格合并 1 2 new`、配置里的 `global_models = ["1"]` 都能正确匹配到对应模型文件。
- **全局通用开关**：`/风格全局启用` 让一个模型对所有群聊（含未绑定群）生效；也可以在 WebUI 插件配置 → 回复后微调 → 「群聊通用模型 ID」中直接填写模型 ID。通用模型默认优先。要给指定群使用自己的模型，在「群绑定与模型」中开启该群的「优先使用本群模型」。
- **跨群融合和挂载**：两份风格模型可以来自不同的群。融合后会记录来源群，用 /风格启用 <融合模型> <目标群号> 或「群绑定与模型」挂载到任意已绑定的目标群。也可以在目标群的「使用模型」中同时填入多份模型。
- **按 QQ 号区分身份**：分析时用临时编号区分同名成员，结果通过消息来源映射回实际 QQ 号。回复时根据会话和被回复的消息 ID 查找来话。
- **消息屏蔽**（WebUI 配置）：屏蔽用户 QQ 号（其消息不收集进模型）、**跳过收集本人消息**（默认开启：机器人自己的消息不会进模型，自动识别机器人账号，识别不到可手动填「本人 QQ 号」）、自动屏蔽带 `/` 的句子、自动屏蔽 QQ 机器人与官方机器人。
- **字句黑名单**（WebUI 配置）：填写一个字句后，消息文本**完整包含**该字句的消息不会收集进模型（整句子串匹配——例如填写「修仙」，只有完整出现「修仙」二字才会被跳过，只含单个「修」字不受影响）；已收集的消息在下次分析时也会被过滤。
- **配置驱动群绑定**：要收集的群与每个群使用的模型都可以直接写在插件配置的「群绑定与模型」里，从配置删除的群自动解绑；命令绑定的群不受配置同步影响。
- **模型编辑**：删除不符合场景的语句/场景，保证内容一致性；重命名、删除模型。
- **黑名单过滤**：语句含义与黑名单高度相似（embedding 语义相似度，失败自动降级 LLM 判定/字面相似度）时自动过滤；黑名单条目可填含义描述、限定模型、开启通用拉黑，且可在 WebUI 插件配置中直接编辑。
- **融合同样执行黑名单过滤**：模型融合结果会同时执行字句黑名单与语义黑名单过滤，融合完成提示会显示各剔除条数。
- **微调前黑名单**（WebUI 插件配置 → 微调前黑名单，默认关闭）：AI 生成回复草稿后、风格微调之前，先把草稿中出现的黑名单词删掉，再进行风格微调——**仅支持中文词条**（词条必须含中文才生效，纯英文、数字、符号与 emoji 词条无效）；字面匹配为整词/子串匹配（例如填写「涩涩」，草稿中出现「涩涩」就会被删除，只含单个字的不会误伤）；可开启**语义换词匹配**：删除会基于「没删前的整句话」理解意思后进行，**尽量保持原有意思**——删除造成句子不通顺或丢失语气时允许补字词或换近义表达（例如删「属实」后可补「是」，删「绷不住了」后可写「难绷」），**只要字面不出现黑名单词即可**，同义换词/变形/谐音表述也会一并删除；**语义换词匹配生效后直接返回删词补意后的文本，不再进行回复后风格微调**（删词补意本身已保持原意并贴合「删词补意风格」，避免二次改写失真）；**仅字面删词命中时仍会继续回复后微调**；可配合**删词补意风格**下拉选择删词后整句话的语气措辞倾向（无 / 温柔 / 自然（像正常人聊天）/ 活泼 / 直爽 / 软萌 / 沉稳 / 冷漠 / 热情，默认「无」= 什么都不额外加，选其他风格时删词补意后的句子会尽量贴合该风格；还可选「自定义」并用「自定义风格描述」输入框自由描述想要的语气，如"像东北老铁唠嗑"，留空则不注入）；删除后草稿为空或只剩标点时终止发送；微调失败或超时时仍返回删词后的文本，保证黑名单词不会出现在最终回复里。
- **回复后轻度微调**：AI 先生成草稿，插件默认从启用的风格模型提取群友的表达习惯和群风格摘要，再按所选强度调整措辞和句子节奏。整体风格模式使用风格档案。按场景模式对所有生效模型的命中场景统一排序，得分高的先占用参考字数。完全未命中时，从普通场景中随机选取最多 3 个，只参考表达习惯。本地 WebUI 的「最近一次微调」显示微调前后句子、参考方式、简短的表达风格和最终采用情况。
- **语义场景检索**（默认关闭）：风格参考方式为「按场景」时，可开启语义检索并在「向量模型来源」下拉框中选择 MaiBot 的 `embedding` 或 `image_embedding` 任务。后者需要支持文本向量化的多模态模型。具体模型由 MaiBot 的「模型分工」选择，索引状态会显示实际返回的模型名。群梗和专名优先按关键词及真实前文查找，命中不明确时使用向量补召回。后台只为新建或变更的场景生成向量，索引写入插件数据目录的 `style_scene_vectors_v1.sqlite3`，模型 JSON 可继续完整保存。插件配置页可查看索引进度和最近一次实际送入微调的场景来源。向量服务会接收场景描述、范例含义及未可靠匹配时的来话。
- **回复乱码拦截**（WebUI 插件配置 → 乱码拦截，默认开启，可随时关闭）：在风格微调之后检查最终回复文本，命中乱码规则时自动要求回复器重新生成（由 MaiBot 提供重试次数）。重试用尽仍命中时终止发送，防止把模型输出的乱码/指令残片发到群里。内置检测：指令片段泄漏（如"为起点按序取字"这类任务残片）、带具体值的内部 ID 或成组调试字段泄漏、消息模板泄漏（`<message>`、`[图片：]` 等）、OneBot 消息 JSON 原样泄漏、编码乱码（替换符/锟斤拷等）、推理过程泄漏（"按之前的推算""原样输出"等）。「命中后重新生成」开关可只记录日志不拦截；「自定义检测正则」可按行追加自己的规则（不区分大小写，无效正则自动跳过）。
- **可调微调强度**：WebUI 插件配置 → 回复后微调 →「微调强度」滑块（0~100）：0 = 跳过风格微调；30 = 轻度（默认，只改几个词）；50 = 中等（适当调整用词语气）；80+ = 明显贴合群聊风格。数值越大，允许改动的措辞越多，当前风格模型请求的采样温度为 0.2。草稿里可识别的联系与交付动作及其明确条件会逐字保留。
- **补词设置**：在「回复后微调」里设置最低字数，默认 5 字，只计算汉字、字母和数字。达到字数时，要求微调模型自然补词并保留原意。低于字数时默认跳过风格微调，可开启「短句先判断再微调」，让同一次模型请求结合来话决定是否改。
- **不用符号表达情绪**（WebUI 插件配置 → 消息屏蔽 →「不用符号表达情绪」，默认开启）：微调与删词补意时要求 LLM 不用波浪号、省略号（如 `~`、`～`、`……`）等符号来营造语气或情绪，情绪一律用中文文字自然表达，避免显得不像真人聊天；关掉则放行符号。
- **微调模型任务名**：默认使用 planner。在同一次请求里判断是否需要语义换词，或参考群风格和被回复的那条来话做措辞微调。程序校验可识别的事实、动作、明确否定与承诺，校验失败时沿用草稿处理结果。
- **融合进度私聊通知**：配置触发融合会私聊发送进度到「进度私聊 QQ 号」：0% 开始、30% LLM 融合中、70% 黑名单过滤中、100% 完成（含剔除条数）；失败、跳过、找不到模型等也会通知；未配置或非好友时静默跳过。

## 快速开始

> 在 MaiBot WebUI 的插件配置页可设置群绑定、模型融合、模型精简和回复后微调。

1. 将本目录放入 MaiBot 的 `plugins/` 目录，在 WebUI 插件管理页启用「聊天风格转译」。
2. 填写管理员 QQ 号（WebUI 插件配置 → 管理员；或编辑 `config.toml` 的 `[owner]`）：
   ```toml
   [owner]
   qq = ["你的QQ号"]
   ```
3. 添加要收集的群（WebUI 插件配置 → 群绑定与模型；或群内 `/风格绑定群 123456789`）：
   ```toml
   [groups]
   [[groups.items]]
   group_id = "123456789"      # 要收集消息的 QQ 群号
   models = []                 # 该群使用的模型（有模型后再填）
   ```
4. 等收集满 `auto_analyze_count`（默认 100）条后自动分析，或手动执行 `/风格生成`；不想等实时收集的话，直接 `/风格拉取历史 <群号> 300` 从 NapCat 回填最近历史消息再分析。
5. 管理员在私聊或本地审核新生成的模型：
   ```
   /风格列表
   /风格详情 <模型名>
   /风格场景 <模型名> 1
   ```
6. 确认无误后用 `/风格启用 <模型名> <群号>` 挂载到指定群，也可以在 WebUI 的「群绑定与模型」里配置。要全局生效，可以设置「群聊通用模型 ID」。
   之后每次 AI 生成回复草稿后，会检索该群风格做微调（原意不变；微调幅度可在 WebUI「回复后微调 → 微调强度」中调整，默认轻度）。

## 命令一览

**参数约定**：`<参数>` = 必填；`[参数]` = 可选（不填时群内执行 = 当前群，私聊执行按说明处理）。
**管理员**在插件配置的「管理员 QQ 号列表」录入真实 QQ 号后，可以使用表里全部命令。名称含空格时可用中文或英文双引号。缺参数时命令会回用法提示。在群里查看受保护的明细时会私聊发给发指令的管理员。

| 命令 | 说明 | 权限 |
| --- | --- | --- |
| `/风格帮助`、`/风格` | 快速帮助 | 所有人 |
| `/风格绑定群 [群号]` | 绑定群并收集对话，群内可省群号 | 管理员 |
| `/风格解绑群 <群号>` | 解绑并删除收集数据 | 管理员 |
| `/风格状态` | 群内查看本群收集进度，管理员私聊或本地可看全部 | 所有人 |
| `/风格生成 [群号]` | 立即后台分析；私聊不指定群号 = 全部绑定群 | 管理员 |
| `/风格拉取历史 [群号] [条数]` | 从 NapCat 回填历史，群内可用 `/风格拉取历史 300条` | 管理员 |
| `/风格列表` | 群成员可看本群生效模型，管理员可看全部 | 所有人 |
| `/风格详情 <模型名>` | 群成员可看本群模型统计，管理员可看详细档案 | 所有人 |
| `/风格场景 <模型名> [序号] [页码]` | 列场景，指定序号分页查看原话 | 管理员 |
| `/风格启用 <模型名> [群号]` | 审核通过并挂载到群；私聊不填群号会提示指定群号 | 管理员 |
| `/风格停用 <模型名> [群号]` | 从群上摘除模型 | 管理员 |
| `/风格全局启用 <模型名>` | 开启全局通用，所有群聊都生效 | 管理员 |
| `/风格全局停用 <模型名>` | 关闭全局通用 | 管理员 |
| `/风格合并 <模型A> <模型B> [新名]` | 融合两个模型（A、B 必填） | 管理员 |
| `/风格删除语句 <模型名> <语句ID> [场景序号]` | 删除指定语句，ID 重复时加场景序号 | 管理员 |
| `/风格删除场景 <模型名> <场景ID或序号>` | 删除整个场景 | 管理员 |
| `/风格重命名 <模型名> <新名>` | 重命名模型 | 管理员 |

## 数据与隐私

- 收集的对话与黑名单存放在插件数据目录 `data/plugins/local.chat-style-translator/` 下。
- 风格模型以 JSON 文件保存在**模型目录**（`config.toml` 的 `storage.model_dir`，默认 `data/plugins/local.chat-style-translator/models/`），每个模型一个文件，可直接手动编辑、重命名或增删，改动立即生效。
- 生成、融合、精简或编辑模型时同步更新小型风格档案。手动导入或改过的 JSON 在首次发现后补建档案。默认「整体风格」下，回复微调和模型列表读取档案，完整 JSON 用于保留原话和前文、审核、融合或按场景参考。
- 消息记录在 `messages/<群号>.json`，黑名单在 `blacklist.json`；每个群的消息按「每群存储上限」自动裁剪，只保留最近的条数（默认 500），不会无限增长。
- 分析成功后清理本轮取用的消息快照，保留分析期间新收集的消息和失败批次，供后续分析。执行 `/风格解绑群` 会删除该群的收集数据。
- 修改 `storage.model_dir` 后需重载插件生效；更换目录不会自动迁移旧模型，需手动移动文件。

## 工作原理

1. `HookHandler("chat.receive.after_process")` 异步收集绑定群消息（消息完成轻量预处理后触发，不改写消息、不阻塞主链），解析 @ 对象与引用对象作为「跟谁说话」线索；收集时执行消息屏蔽与字句黑名单过滤。
2. `StyleAnalyzer` 用 `llm.generate` 分批分析对话窗口，输出「整体风格 + 群友档案 + 多场景 + 代表性语句（含说话对象与含义）」，再融合成完整模型；分析前按字句黑名单过滤消息，分析后按语义黑名单过滤语句。
   遇到明确引用且原消息也在收录范围时，范例可带 `context` 保存那句前文。`text` 继续保存群友的接话，两个字段算一条范例。旧模型可继续用于回复。

3. `SemanticFilter` 优先用 `llm.embed` 余弦相似度对比黑名单；embedding 不可用时降级为 LLM 意思判定，再降级为字面相似度。
4. `HookHandler("maisaka.replyer.after_response")` 在草稿生成后，默认根据启用模型里的整体风格资料和实际例句的表达习惯润色。选择「按场景」时，先检索相关场景，再提取语言风格。普通场景不发送例句原话和接话步骤，特殊场景仅在真实前文高度吻合时可附原话参考。插件复核常见数字、时间、链接和明确动作。
5. 模型融合（配置触发或 `/风格合并`）会生成全新模型文件，融合结果同时执行字句与语义黑名单过滤；融合进度（0%/30%/70%/100%）与结果、失败原因私聊发送给配置的 QQ。

## 排错

- **管理命令提示权限不足**：确认 WebUI 插件配置 → 管理员 中填了你的 QQ 号（或 `config.toml` 的 `owner.qq`），保存后重载插件。
- **分析一直失败**：查看日志中 `chat_style_translator` 相关输出；确认「分析参数 → 分析模型任务名」有效，或留空使用默认模型。
- **模型目录用不了/换机器后模型不见了**：`storage.model_dir` 支持**绝对路径**（如 `D:\StyleModels`）与**相对路径**（相对插件数据目录，如 `models`）。配置写死某台机器的绝对路径（如 `D:\OldStyleModels`）会导致换电脑或换用户目录后模型目录不存在、插件静默用不了——建议新装时留空用默认目录，或填相对路径；迁移数据 = 把旧目录下的全部 `*.json` 模型文件复制到新目录，再改配置并重载插件（更换目录不会自动迁移）。
- **挂载后没生效**：确认该群已绑定并执行过 /风格启用。若使用单独的群设置，请关闭「模型目录自动生效」。检查「回复后微调 → 启用微调」是否开启。
- **黑名单过滤太严/太松**：调整「黑名单 → 相似度阈值」（0.5 宽松，0.9 只过滤含义几乎一致的语句）。
- **配置触发融合没反应**：确认「模型融合 → 执行融合」已打开并保存，模型 A/B 填的是模型文件名、模型名或 ID（`/风格列表` 可查看）；日志会输出 `配置触发融合` 相关结果；融合完成后在「模型融合」节下方通过 `/风格列表` 查看新模型。
- **融合后原模型被覆盖了？** 不会：融合结果会生成全新的模型文件（新的 `m_2026…` 文件名），原模型保持不变；更新已有模型（启用/重命名/删语句）才写回原文件。
- **融合后模型还是太大**：把「模型融合 → 去重强度」调成「激进精简」；「融合比例」只影响重复语句优先保留哪一方，不会减少重复本身。
- **单个模型太大想压缩**：WebUI 插件配置 → 模型精简，填写模型并打开「执行精简」保存配置即可（纯本地去重，秒出结果，原模型不动）；觉得压得不够狠可把去重强度调成「激进精简」。精简进度与结果私聊发送，未配置「进度私聊 QQ 号」或非好友时静默不发送。
- **字句黑名单没生效**：确认字句已保存；黑名单只影响之后收集的消息，已收集消息会在下次分析时被过滤；「完整包含」是整句子串匹配，单字（如「修」）不会匹配「修仙」。
- **微调前黑名单没生效**：确认 WebUI 插件配置 → 微调前黑名单 →「启用微调前黑名单」开关已打开并保存，且黑名单词已填写；该功能只作用于 AI 回复草稿（微调流程），不影响收集与模型分析；**只支持中文词条**，纯英文/数字/符号/emoji 词条无效（会被忽略）；黑名单词删完后草稿为空或只剩标点时会终止发送。
- **词条在草稿里以换词/变形出现（如「涩涩子」）或删词后句子不通顺**：打开「微调前黑名单 → 语义换词匹配」开关（默认关闭）：删除会基于没删前的整句话理解意思后进行，尽量保持原有意思——删除后不通顺或丢语气时会补字词或换近义表达（如删「属实」后补「是」，删「绷不住了」后写「难绷」，只要字面不出现黑名单词即可），同义换词/变形/谐音也会一并删除；**注意：语义换词匹配生效后不再进行回复后风格微调**（直接返回删词补意后的文本），只做了字面删词（未开启语义匹配、或语义删除退回字面结果）时仍会继续回复后微调；语义换词和风格微调共用一次模型请求。语义换词未生效时可在该请求中进行风格微调，结果异常时沿用字面过滤后的草稿。
- **微调太慢或没效果**：检查「最近一次微调」里的结果，并确认「微调模型任务名」配置正确。整次微调由「微调 Hook 超时(秒)」限制。模型调用失败或结果未通过校验时，采用草稿处理结果。
- **微调幅度不合适**：在「回复后微调 → 微调强度」中调整（0 = 跳过风格微调，80+ = 明显贴合群聊风格），任何强度下原意不变。
- **微调/删词补意总带 ~、～、…… 等符号表达情绪**：确认 WebUI 插件配置 → 消息屏蔽 →「不用符号表达情绪」为开（默认开）。该开关开启时，风格微调与删词补意的提示词里会明确要求不用这些符号表达情绪。
- **融合没收到私聊通知**：确认「分析参数 → 进度私聊 QQ 号」已填写且与 bot 是好友；融合进度（0%/30%/70%/100%）与失败原因都会私聊发送。
- **某人的消息还在被收集**：检查「消息屏蔽 → 屏蔽用户 QQ 号」是否已添加该 QQ；屏蔽与生成都只影响之后的分析。
- **模型里混进了机器人自己的话**：确认「消息屏蔽 → 跳过收集本人消息」为开（默认开）；NapCat 适配器默认已过滤本人消息，若自定义适配器未过滤且自动识别失败，在「本人 QQ 号」里手动填写机器人 QQ。
